Duplication and maintainability
- spike.ExtractToken duplicates trace.ExtractToken; playback/spike separately parse part IDs. Centralize protocol parsing so classification, authentication, enforcement, and redirect construction agree.
- Live metadata structs/interpretation duplicate indexed media ingestion and have already drifted materially.
- Effective policy reports one final scope for every rejection, so a device override of an unrelated field can mislabel an inherited global/user restriction. Preserve per-field provenance.
- preferDirectPlay is accepted and merged but unused; routingMode is persisted but does not select transport. Treat these as unfinished behaviors and expose capability status clearly.
- Existing playback tests predominantly use MemoryStore, masking its persistence differences from PGStore; the fake origin also puts mode booleans inside decision, unlike the parser and checked-in fixture, and tests fail to check recorded modes.
Suggested roadmap
1. Correctness release: fix findings 1–7; add SQL-backed full negotiation→session reload→media tests, property tests for redirect authorities, and the same enforcement matrix across ingress modes.
2. Protocol compatibility: sanitized captures from real clients, JSON/XML decision handling, validated capability profiles, multipart playback and retry/resume coverage; make release acceptance depend on actual client evidence.
3. Operator experience: accurate per-field policy explanations, session lifecycle visibility, actionable distinction between missing state and database failure, and a policy preview against an item/device.
4. Later additions: implement routing preferences and fallback only after client evidence justifies them; preserve the documented decision to defer metadata-array filtering.
